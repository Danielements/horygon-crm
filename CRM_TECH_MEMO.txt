3. Modulo ricambi/chat: stato attuale

File principale
- `src/routes/parts.js`

Canali inbound gestiti
- WhatsApp webhook: `GET/POST /api/webhook/whatsapp`
- Telegram webhook: `POST /api/webhook/telegram`

Funzioni ricambi principali gia implementate
- Triage richiesta ricambi
- Raccolta progressiva dati cliente
- Stato conversazione e richiesta in DB
- Lookup cristalli via RTWS_LISTINI `CheckEurocodeDaTargaOE2`
- Gestione varianti RTWS e selezione via numero
- Creazione articolo da richiesta ricambi
- Creazione preventivo bozza
- Generazione PDF preventivo
- Invio PDF e link pubblico su WhatsApp / Telegram
- Chiusura automatica richieste inattive
- Logging eventi tecnici richiesta

Vision / immagini
- Download media inbound WhatsApp
- Download media inbound Telegram
- Analisi immagini con OpenAI Vision
- Fusione dati immagine + testo nel flow intake
- Placeholder inbound piu leggibili: `[foto ricevuta]`, `[documento ricevuto]`, `[audio ricevuto]`
- Logging quando la vision viene eseguita o saltata

Note importanti sul flow ricambi
- Le richieste aperte oggi sono considerate solo con stati:
  `nuova`, `in_lavorazione`, `in_attesa_dati_cliente`, `in_attesa_verifica_tecnica`, `oe_trovato`
- `preventivo_pronto` non e piu considerato stato aperto per il riuso del contesto
- Dopo conferma PDF o rifiuto PDF, la richiesta viene chiusa logicamente come `completata`
- Il contesto storico viene pescato solo da richieste ancora aperte

Problemi gia emersi e fix applicati
- `options is not defined` nel flow AI: corretto
- RTWS state code `-100` non piu trattato come errore fatale
- richiesta vecchia riusata anche dopo preventivo: corretto
- placeholder foto prima appariva come `[messaggio senza testo]`: corretto
- Telegram photo poteva saltare Vision per MIME generico: corretto preferendo MIME dichiarato del messaggio

Problemi da ricordare
- In chat CRM oggi si vede il placeholder testo della foto, non ancora una preview visuale vera
- Per mostrare l’allegato nel frontend serve estendere il rendering dei messaggi leggendo `message_type`, `media_url`, `media_mime_type`, `media_metadata_json`

9. Query SQLite utili per debug

Ultime richieste ricambi
SELECT id, request_uuid, user_phone, channel, status, original_message, plate, requested_part_text, oe_code, updated_at
FROM parts_requests
ORDER BY id DESC
LIMIT 20;

Richieste aperte ricambi
SELECT id, request_uuid, user_phone, status, last_message_at, updated_at
FROM parts_requests
WHERE status IN ('nuova','in_lavorazione','in_attesa_dati_cliente','in_attesa_verifica_tecnica','oe_trovato')
ORDER BY updated_at DESC;

Eventi di una richiesta
SELECT id, event_type, event_message, event_source, payload_json, created_at
FROM parts_request_events
WHERE parts_request_id = ?
ORDER BY id DESC;

Stato intake di una richiesta
SELECT parts_request_id, stage, pending_slot, pending_question, slots_json, updated_at
FROM parts_request_intake_state
WHERE parts_request_id = ?;

Messaggi di una conversazione ricambi
SELECT wm.id, wm.direction, wm.channel, wm.message_type, wm.body_text, wm.media_url, wm.media_mime_type, wm.delivery_status, wm.error_message, wm.created_at
FROM whatsapp_messages wm
JOIN whatsapp_conversations wc ON wc.id = wm.conversation_id
WHERE wc.parts_request_id = ?
ORDER BY wm.id DESC;

Ultime conversazioni
SELECT id, user_phone, parts_request_id, status, last_message_at, updated_at
FROM whatsapp_conversations
ORDER BY id DESC
LIMIT 20;

Richieste con errori integrazione
SELECT id, request_uuid, user_phone, status, original_message, updated_at
FROM parts_requests
WHERE status = 'errore_integrazione'
ORDER BY updated_at DESC;

Eventi errore ricambi
SELECT pre.id, pre.parts_request_id, pre.event_message, pre.payload_json, pre.created_at
FROM parts_request_events pre
WHERE pre.event_type = 'errore_integrazione'
ORDER BY pre.id DESC
LIMIT 50;

Controllo vision eseguita/skippata
SELECT id, event_type, event_message, payload_json, created_at
FROM parts_request_events
WHERE parts_request_id = ?
  AND event_type IN ('media_ai_analysis','media_ai_skipped','errore_integrazione')
ORDER BY id DESC;

Varianti OE salvate per richiesta
SELECT id, oe_code, description, list_price, source, created_at
FROM parts_request_oe_results
WHERE parts_request_id = ?
ORDER BY id ASC;

Prodotto e preventivo collegati a una richiesta
SELECT id, request_uuid, linked_product_id, linked_preventivo_id, status
FROM parts_requests
WHERE id = ?;

Dettaglio preventivo con token pubblico
SELECT id, codice_preventivo, stato, totale, public_token, data_preventivo, note
FROM preventivi
ORDER BY id DESC
LIMIT 20;

Righe preventivo
SELECT pr.id, p.codice_interno, p.nome, pr.descrizione, pr.quantita, pr.prezzo_unitario, pr.totale_riga
FROM preventivi_righe pr
LEFT JOIN prodotti p ON p.id = pr.prodotto_id
WHERE pr.preventivo_id = ?;

Giacenza prodotto da movimenti
SELECT p.id, p.codice_interno, p.nome,
       COALESCE(SUM(CASE
         WHEN mm.tipo IN ('carico','reso','rettifica') THEN mm.quantita
         WHEN mm.tipo = 'scarico' THEN -mm.quantita
         ELSE 0
       END), 0) AS giacenza
FROM prodotti p
LEFT JOIN magazzino_movimenti mm ON mm.prodotto_id = p.id
WHERE p.id = ?
GROUP BY p.id, p.codice_interno, p.nome;

Ordini da preventivo
SELECT id, codice_ordine, tipo, stato, preventivo_id, totale, data_ordine
FROM ordini
WHERE preventivo_id = ?;

Ultimi errori applicativi
SELECT id, livello, origine, route, metodo, status_code, messaggio, creato_il
FROM system_log
ORDER BY id DESC
LIMIT 50;

Ultime chiamate AI
SELECT id, provider, modello, operazione, token_input, token_output, token_totali, costo_stimato, stato, errore, creato_il
FROM ai_usage_log
ORDER BY id DESC
LIMIT 50;

12. Note operative per domani

- Se una foto non viene capita, controllare prima `parts_request_events`
- Se compare `media_ai_skipped`, il motivo e nel payload
- Se compare `media_ai_analysis` ma gli slot restano vuoti, il problema e nel merge dati
- Se la chat riusa un contesto sbagliato, verificare lo stato della richiesta precedente
- Se il PDF non parte su WhatsApp, controllare `whatsapp_messages.delivery_status` e `error_message`
- Se Telegram/WhatsApp non rispondono ma il CRM si aggiorna, guardare l’outbound in `whatsapp_messages`
